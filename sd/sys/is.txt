  THROUGH the nozzle, so G28 Z / G30 with the sensor on risks a crash and
  corrupts the trigger height regardless. Do not home Z. Instead:

    1. Establish REAL physical clearance first — jog the bed clear by eye.
    2. G92 Z250      ; fake datum, marks Z homed so G1 X/Y are accepted
    3. XY freely. NO Z MOVES AT ALL for the rest of the session.

  M208 Z-10:300, a believed 250 leaves 50mm of accepted opening move and 260mm
  of accepted closing move, neither related to where the bed actually is.
  Verified 21/08/2026: homex.g/homey.g DO move Z (G1 H2 Z5 then Z-5) but the
  pair is self-cancelling, so homing X and Y is safe given >5mm real clearance,
  and the faked 250 survives homing intact.

  AFTER the session: remove the accelerometer, THEN G28 (or at minimum G28 Z)
  before anything probes, trams, meshes or prints. The Z datum is junk until
  re-homed, and any heightmap applied against it is displaced bodily. M18 also
  clears it — it drops the homed flags, which is a safe way to park.

  Restore after: M201 X35000 Y35000 / M203 X30000 Y30000 / M593 P"zvd" F127 S0.05
  NOTE S0.05 is the RRF 3.7.0-beta.3 DEFAULT, confirmed by the M593 report on

ANALYSIS METHOD
  Sample rate 1607 Hz (read from CSV footer, do not assume)
  Drop final row before parsing — it is "Rate NNNN, overflows N", not data
  Columns: Sample,X,Y,Z  → Y column = machine Y at I65
  Cruise window: samples 250:950
  Detrend, Hanning window, rFFT, amplitude = |FFT|/n*4
  Check clipping: count |a| >= 1.995 — ±2.000g is hard full scale at 14-bit
  Baseline runs clipped 13-14 samples on Y; if clipping rises, amplitude
  comparison is understated and invalid.

PREDICTIONS — STATED IN ADVANCE
  312 Hz SHOULD LARGELY DISAPPEAR.
    Evidence: collapsed 0.197 -> 0.032 (6x) when sensor moved from nozzle to
    extruder body, i.e. above the probe mount. A 6x drop across that joint means
    the compliance is below it — in the hotend/ALPS/water block stack.
    Loose screws are exactly that. Expect large reduction.

  204 Hz SHOULD SURVIVE.
    Evidence 1: dropped only 1.8x across the same joint (0.370-0.498 -> 0.210),
    matching pure lever-arm geometry. Sensor moved 70mm below rail to 40mm above;
    predicted ratio 40/70 = 0.57, measured 0.42-0.61. Geometry, not a fix.
    Evidence 2: X-position test, Y sweep at three toolhead positions —
      X=20   197Hz (0.057)   rms 0.234
      X=200  204Hz (0.222)   rms 0.312
      X=380  216Hz (0.040)   rms 0.233
    4-5x larger at mid-span, frequency held. Antinode centre, nodes at ends =
    mode shape of the X beam (20x20x3mm 6063, pinned by Y carriages).
    Diagnosis: first torsional mode, driven by toolhead CoM offset below the
    tube shear centre. A loose hotend screw cannot produce a mid-span antinode.

  IF 204 Hz ALSO DROPS SUBSTANTIALLY, the beam-torsion diagnosis is wrong.
  Two prior hypotheses already failed this session (encoder calibration;
  rail ball-pass). Do not assume — check.

Conditions exactly as specified above. Cold (~23C), shaper off, D4 verified on
all four drivers individually, 3 runs, via macros/is_recheck.g. Analysis per
ANALYSIS METHOD; the script was validated FIRST by reproducing the X=20 row

  Y cruise rms       0.477 0.477 0.537 -> 0.497   0.497 0.523 0.464 -> 0.495   unchanged
  ~204Hz amplitude   0.370 0.369 0.498 -> 0.412   0.418 0.402 0.228 -> 0.349   SURVIVES
  ~204Hz frequency   218 216 211 Hz               213 216 211 Hz               held
  ~312Hz             0.197 (single capture)       0.102 0.051 0.057 -> 0.070   ~3x DOWN
  Y clipping         13-14 samples                9 / 4 / 4                    fell

312 Hz — CONFIRMED LARGELY GONE. In runs 2 and 3 there is no distinct peak at
all: the band maximum wandered to 294 and 303 Hz at ~0.05g, which is broadband
floor, not a mode. Only run 1 retains a real line, 315Hz at 0.102. The loose
ALPS screws WERE this mode, exactly as the 6x sensor-relocation collapse
predicted.

204 Hz — CONFIRMED SURVIVING. Means moved 0.412 -> 0.349, but the baseline
spread alone was 0.369-0.498 and the post spread is 0.228-0.418. They overlap
heavily; this is inside the ~15% scatter. THE BEAM-TORSION DIAGNOSIS STANDS. It
remains a stiffness/geometry problem that shaping will not fix.

VALIDITY: clipping FELL, so by the test above the comparison holds. Note the
direction — clipping understates amplitude, so the baseline was understated
slightly MORE than the post-fix runs. That makes the 312Hz reduction marginally
larger than measured, not smaller, and means the 204Hz "no change" is if
anything a touch optimistic.

BOTTOM LINE: overall vibration is UNCHANGED, because 204 Hz dominates the energy
and 204 Hz is untouched. The screw fix bought a clean probe load path, not a
faster machine. The 600-700 mm/s ceiling is unmoved.

INCIDENTAL: the 127Hz band sat at 126.3 / 126.2 / 126.2 Hz across all three
runs. The top panel and the temporary slab have NOT moved the gantry mode, so
M593 F127 is still correctly placed. Cold only — the hot check after the rail
shim still stands.

BELT A/B AMPLITUDE ASYMMETRY — 22/08/2026
--------------------------------------------------------------------------------
Resonance-lab "Belt tension" plugin (60-180Hz sweep) flagged belts "97% similar,
peaks 129/146Hz" but the capture was 6-36% clipped and the actual sweep rate
(fitted ~3.2Hz/s) didn't match the requested 2Hz/s — the plugin result is not
trustworthy. PF gauge (2.6/2.6) and Spectroid (120 / 120-123Hz) directly measure
matched belt tension and are believed over the plugin.

Replicated the plugin's excitation with plain G-code instead: on this CoreXY, a
pure X or Y move drives BOTH belts (see homex.g), but a 45-degree diagonal move
isolates one belt pair. dX=+dY drives only the X pair (70.0+71.0, back-right +
front-left). dX=-dY drives only the Y pair (72.0+73.0, front-right + back-left).
macros/is_diag.g runs 3 diagonal sweeps each way near centre at the same clean,
non-clipping conditions as is_xpos.g. Zero clipping on all 6 captures.

  Y rms   Diagonal A (X pair)   0.371 / 0.339 / 0.352  -> 0.354
          Diagonal B (Y pair)   0.252 / 0.255 / 0.277  -> 0.261

No overlap across 6 runs (A min 0.339 > B max 0.277) — a real ~35% gap, not
scatter. Frequency itself does NOT show a real split: peaks wander 124.0-130.9Hz,
within one 2.3Hz FFT bin of each other — same ~124-130Hz gantry mode already
documented above, not two different modes as the plugin implied.

NOT belt tension (already ruled out directly by gauge + Spectroid, and both
diagonals excite the same mode frequency, not different ones). Reads as the two
belt-drive load paths coupling into the gantry unevenly — a stiffness/coupling
asymmetry between the X-pair path (back-right+front-left corners) and the Y-pair
path (front-right+back-left corners).

NOT yet linked to the left/right X-position asymmetry above. That test used a
pure Y-sweep, which drives both belts together — a different axis of comparison,
implicating different corners. Treat as a separate open structural finding until
a test connects them directly.

METHOD WARNINGS LEARNED THE HARD WAY
  - Single captures have ~15% run-to-run scatter. Three runs minimum before
    trusting any modest effect. An apparent I1000->I500 improvement vanished
    entirely once repeats were run.
  - M569.1 with parameters DROPS DRIVERS TO OPEN LOOP. Re-home after, and
    verify with M569 Pxx.0 (not M569.1, which reports PID but not mode).
  - Resonance-lab plugin sweep is quantisation-limited above ~100Hz: at 80
    steps/mm and its 60mm/s^2-per-Hz excitation, 135Hz = 2.2 microsteps of
    commanded motion. Cannot usefully probe 204Hz. Use decel ring-down instead.

WHERE THIS LEAVES INPUT SHAPING — 22/08/2026
